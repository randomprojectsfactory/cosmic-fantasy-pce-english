# Adapting Cosmic Fantasy to PC Engine CD

The aim is to bring the Collection's English localisation to the original PCE presentation while retaining its Japanese voices, music and artwork. The PCE executable has its own scripts, banked memory, text consumers and graphics pipeline, so an English script alone cannot supply a working localisation.

## Native English and interface coverage

The adaptation covers story scripts and separate native consumers for menus, shops, item names and descriptions, status displays, system messages and combat. These consumers include duplicated battle modules and UI-specific number fields. They must preserve control bytes, dynamic values and caller bank mappings rather than treating each screen as plain text.

English text is measured against the usable horizontal space before wrapping. Pagination holds the original event until the final acknowledgement, preserving choices and continuation. Menu cells, item quantities, prices, ammunition and cursor margins require their own limits; dialogue wrapping cannot safely be reused for every UI.

## Combat copy correction

The English reference reverses the character/enemy roles in affected attack messages. The adaptation fixes the actor/target operand order against the native PCE message logic, so the displayed attacker and target correspond to the action. Battle-command headings also distinguish Yu and Saya in both battle modules.

## Why subtitles required a new system

The cinematics are generated by the console's own scene code, graphics resources and CD audio. There is no standard subtitle stream to switch on. Captions must be rendered by new code inside the game and remain synchronized with playback while the native scene continues.

The subtitle set contains **364 caption entries across 59 audio tracks**. Long spoken passages need readable line breaks and suitable display durations. Caption state must reset on new playback, scene changes and skips, including sequences that return to ordinary gameplay.

Graphics memory is shared with the scene. Caption tiles, palette use and sprite-table updates must preserve what the native code is displaying, even when scene dimensions change or another graphics upload runs. Backup and restoration paths prevent subtitle cleanup from leaving coloured fragments or overwriting native graphics. The renderer restores its caller's memory-bank mappings and separates subtitle-owned state from native scene state.

## Location text and scene boundaries

The Planet Norg card is driven by native scene entry and exit rather than the normal spoken-audio schedule. It has a separate caption lifecycle, preserving the Japanese title and planet artwork. Both natural completion and skipping clear its caption state before later speech begins. Japanese staff credits in the automatic pre-title introduction are retained.

## Display and save/load transitions

Menus, portraits and battles share rendering resources. Clearing a text window must respect neighboring choice windows, native sprite data and the area restored when a menu closes. The save/load correction clears transient party-occlusion flags for all five party slots before the native map reconstruction, rather than repairing only Yu after loading.

## Disc integrity and distribution

Only data Tracks **02 and 99** change. All other tracks remain byte-identical, track lengths are preserved, and changed raw Mode 1 sectors have regenerated error-detection and correction data. Each patch applies directly to the unmodified Japanese track; no earlier English build is required.

The published package is assembled from an explicit allowlist: xdelta differences, a source/output hash manifest, a patcher, documentation and screenshots. It contains no disc image, voice or music track, save, BIOS, or separate game-resource archive. Applying the package must reproduce the expected whole-track SHA-256 values.
